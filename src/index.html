The uncomplicated self-service app for big and small organizations

Windows macOS Linux

People install the apps you approved with one click, and furnish keeps them updated with each system's own package manager. The catalog is a git repository on your git server. Larger organizations connect the systems they already operate: device management, sign-in, the load balancer and the log system.

It runs on the systems you already have

furnish brings no server of its own. Each computer pulls the catalog from git and installs with the system's package manager. Choose your size to see which of your systems furnish uses.

Your git server

GitHub, GitLab, Gitea, Forgejo or any other git server, with public or private repositories. One repository is the catalog.

The systems' package managers

winget on Windows, Homebrew on macOS and the system's package manager on Linux, plus installer files you keep in the repository.

Device management

A policy from Intune, Group Policy or your MDM decides which collections people get and locks settings.

Small teams

Running in an afternoon

For a team whose people manage their own computers. There is nothing to host and no directory to connect.

  1. Put your apps in a git repository

    One short file per app says which package to install on which system. Start from the example collection with ten real apps.

  2. Install furnish on each computer

    The download for Windows, Homebrew on macOS, the signed package repository on Linux. Install instructions

  3. Add the repository

    Paste its URL on the Collections page, or run furnish collection add <url>. From then on, furnish picks up new apps and updates by itself.

  • furnish check in your repository's CI finds broken app files before anyone installs them.
  • When an install fails, furnish offers the version that last worked.
  • The app follows the system's language: English, German, French, Spanish, Italian, Polish, Portuguese or Dutch.

Large organizations

Rules your device management enforces, reports your log system keeps

furnish uses your device management, identity provider, load balancer and log system, so it fits the processes you already have for compliance and operations.

Enforce what people get

  • A policy from your device management presets collections people can't remove, answers their questions, locks settings and installs apps on first start.
  • People without administrator rights can install the apps of your preset collections through the furnish service. You choose who may.
  • Preset collections only accept changes signed with your keys.
  • Your organization's name, logo and color replace furnish's.

Settings, not only apps

  • An entry in the catalog can be a configuration: a VPN connection, registry values, Windows features or firewall rules. furnish includes Microsoft's DSC resources for them.
  • Your device management can install such entries on first start, and furnish shows whether they are still in place.
  • An entry says how to remove what it set up, so retiring a VPN profile reaches every computer.

apps/acme-vpn.dsc.yaml, shortened

metadata:
  furnish:
    description: Connection to the Acme company network
    dependencies: [ { app: openvpn-client } ]
    uninstall:
      - name: delete the configuration
        type: Microsoft.DSC.Transitional/RunCommandOnSet
        properties: { executable: powershell.exe, … }
resources:
  - name: OpenVPN configuration
    type: Microsoft.Filesystem.File/Content
    properties:
      path: C:\Program Files\OpenVPN\config\acme.ovpn
      content: …

Keep an audit trail

  • furnish reports each install, update, uninstall and fallback with its outcome, the error, the device and the time. The proxy adds the user from the sign-in, so a computer can't report under someone else's name.
  • Reports go through Vector to your log system. The included Grafana dashboard shows failures per app, the furnish versions in use and devices that stopped reporting.
  • Reports are off until you turn them on, and you can lock the choice. Works councils can review exactly what is sent.

Handle many computers

  • There is no catalog server to scale: every computer pulls from git, so your git server, or a mirror of it, carries the load.
  • Computers download only what they use.
  • A furnish address such as furnish.myorg.tld behind your load balancer replaces the VPN. People sign in with their organization account, and your git server stays internal.
  • A link in an onboarding e-mail sets furnish up for your organization, including first apps such as the VPN client.

The admin guide covers the policy, the service and reports; the endpoint setup has the proxy configurations that CI tests.

For the people using it

People find the apps you approved, see what installing one will do, and get on with their work while furnish installs and updates in the background.

A preview and live progress for each step

Before you install an app, furnish shows what it will do. During the install you follow each step and can stop it.

Recommendations by role

A collection can ask what someone works on, for example software development or design, and recommend the apps for it.

Kits

A kit installs several apps together, such as the apps a designer needs. Required apps are always included; people choose the optional ones.

Automatic updates

furnish installs updates by itself, when the computer isn't busy, so they don't get in the way of work.

An earlier version when an install fails

If installing or updating an app fails, furnish offers the version that last worked and keeps it until the collection changes the app. Administrators decide whether it does.

In the language people work in

furnish speaks English, German, French, Spanish, Italian, Polish, Portuguese and Dutch. It follows the system's language, and people can switch it on the Collections page. Organizations can set it for everyone.

How an app gets into the catalog

Each app is one file in a git repository, written in DSC, Microsoft's open-source configuration format. furnish keeps a copy of the repository on every computer and keeps it up to date.

apps/gimp.dsc.yaml

metadata:
  furnish:
    description: Image editor for photo retouching, …
    categories: [Graphics, Photo]
    icon: icons/gimp.svg
    recommended: "[equals(parameters('role'), 'design')]"
resources:
  - name: gimp
    type: Furnish/Package
    condition: "[not(equals(context().os.family, 'Windows'))]"
    properties: { name: gimp }
  - name: gimp (winget)
    type: Furnish/Package
    condition: "[equals(context().os.family, 'Windows')]"
    properties: { name: GIMP.GIMP.3 }
  1. Describe the app: which package to install, with which package manager, on which systems.
  2. Push the file to the collection's repository.
  3. Everyone with the collection sees the app and can install it with their system's package manager.

Install the alpha

Builds of the main branch; there are no releases yet.

Download for Windows (64-bit)

The alpha isn't code-signed yet, so Windows SmartScreen warns about it: choose More info → Run anyway. A new alpha means a new download; furnish doesn't update itself on Windows yet.

On a Mac with Apple silicon, install furnish with Homebrew. brew upgrade brings each new alpha.

brew install --cask furnish-self-service/tap/furnish

Or download for Mac with Apple silicon

The alpha isn't signed by Apple yet, so macOS blocks it at first: open furnish once, then allow it under System Settings → Privacy & Security → Open Anyway. macOS asks again after each update. Without Homebrew, a new alpha means a new download. For Intel Macs, build it with Xcode's command line tools, Rust and Node.js:

git clone https://github.com/furnish-self-service/furnish.git
cd furnish/gui && npm ci && npm run bundle

furnish comes from a signed package repository, so updates arrive with the system's other updates. Pick the commands for your distribution:

Debian, Ubuntu and their derivatives 
sudo install -d /etc/apt/keyrings
sudo curl -fsSLo /etc/apt/keyrings/furnish.asc https://furnish-self-service.github.io/furnish/gpg-key.asc
sudo curl -fsSLo /etc/apt/sources.list.d/furnish.list https://furnish-self-service.github.io/furnish/alpha/furnish.list
sudo apt update && sudo apt install furnish
Fedora and Enterprise Linux 10 
sudo curl -fsSLo /etc/yum.repos.d/furnish.repo https://furnish-self-service.github.io/furnish/alpha/furnish.repo
sudo dnf install furnish     # Enterprise Linux 10: enable EPEL and CRB first
openSUSE 
sudo zypper addrepo https://furnish-self-service.github.io/furnish/alpha/furnish.repo
sudo zypper install furnish
NixOS 
# flake.nix
inputs.furnish.url = "github:furnish-self-service/furnish";

# configuration.nix, with furnish.nixosModules.default imported
services.furnish.enable = true;

Then add your organization's furnish address or a collection's git URL on the Collections page. To try furnish, add the example collection: furnish collection add https://github.com/furnish-self-service/self-service-example.git.
