Your organization's app store, kept in git.

furnish shows your people a catalog of the apps you curate. They install, update and remove them with one click, without a ticket. Each app is a configuration file in DSC, Microsoft's open-source configuration format, kept in a git repository. furnish runs it on Linux, macOS and Windows.

Install the alpha Read the docs

An app is a file. Your catalog is a repository.

No server, no database, no agent fleet. Put DSC files in git; furnish turns them into an app store.

apps/gimp.dsc.yaml

metadata:
  furnish:
    description: Image editor for photo retouching, …
    categories: [Graphics, Photo]
    icon: icons/gimp.svg
    recommended: "[equals(parameters('role'), 'design')]"
resources:
  - name: gimp
    type: Furnish/Package
    condition: "[not(equals(context().os.family, 'Windows'))]"
    properties: { name: gimp }
  - name: gimp (winget)
    type: Furnish/Package
    condition: "[equals(context().os.family, 'Windows')]"
    properties: { name: GIMP.GIMP.3 }
  1. Write what an app needs, in standard DSC v3: which package, from which package manager, on which system.
  2. Push to the repository your people's furnish follows.
  3. They install it, with the package manager of their system.

Every step, before and while it runs

Before installing, furnish lists each step and the exact command, and whether it needs administrator rights. While it runs, the same list fills in live with times and results. Stop after the current step, or right away.

Questions, then recommendations

A collection can ask what someone works on. The answer recommends the right apps and feeds the options apps use, such as installing just for this user.

Kits

Bundle what a role needs. Required apps always come along; people pick the optional ones.

Updates when the computer is quiet

furnish installs updates automatically, and waits while the CPU, memory or network are busy. Its own work doesn't count.

One thing at a time

Click install on several apps and they queue up. The Activity page shows what runs and what waits, and anything queued can be removed.

Built for the people who run the fleet

One policy, in each OS's own place for managed settings, decides what users see and change.

Users without admin rights

The furnish service installs your collections' apps system-wide on their behalf, and only those, for the people you allow.

Signed all the way

Collections can require commits signed by your keys. furnish's own packages come from a signed APT and RPM repository.

Preset and locked

Hand out collections, answer questions for your people, and lock any setting or option.

Your name, logo and colors

furnish can carry your branding. It keeps text readable whatever your brand color is.

Install the alpha

Builds of the main branch, versioned 0.1.0+alpha.<build>. Updates arrive with your system's own updates.

sudo install -d /etc/apt/keyrings
sudo curl -fsSLo /etc/apt/keyrings/furnish.asc https://furnish-self-service.github.io/furnish/gpg-key.asc
sudo curl -fsSLo /etc/apt/sources.list.d/furnish.list https://furnish-self-service.github.io/furnish/alpha/furnish.list
sudo apt update && sudo apt install furnish
sudo curl -fsSLo /etc/yum.repos.d/furnish.repo https://furnish-self-service.github.io/furnish/alpha/furnish.repo
sudo dnf install furnish     # Enterprise Linux 10: enable EPEL and CRB first
sudo zypper addrepo https://furnish-self-service.github.io/furnish/alpha/furnish.repo
sudo zypper install furnish
# flake.nix
inputs.furnish.url = "github:furnish-self-service/furnish";

# configuration.nix, with furnish.nixosModules.default imported
services.furnish.enable = true;

Download for Mac with Apple silicon

The alpha isn't signed by Apple yet, so macOS blocks it at first: open furnish once, then allow it under System Settings → Privacy & Security → Open Anyway. A new alpha means a new download; furnish doesn't update itself on macOS yet. For Intel Macs, build it with Xcode's command line tools, Rust and Node.js:

git clone https://github.com/furnish-self-service/furnish.git
cd furnish/gui && npm ci && npm run bundle

Download for Windows (64-bit)

The alpha isn't code-signed yet, so Windows SmartScreen warns about it: choose More info → Run anyway. A new alpha means a new download; furnish doesn't update itself on Windows yet.

Then add a collection, for example the example one: furnish collection add https://github.com/furnish-self-service/self-service-example.git.
