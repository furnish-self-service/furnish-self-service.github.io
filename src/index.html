The uncomplicated self-service app for big and small organizations

Windows macOS Linux

Keep the apps you approve in a git repository. People install them with one click, and furnish keeps them updated with each system's own package manager. There is no server to run. Larger organizations add a policy to preset collections, lock settings and let people without administrator rights install.

How an app gets into the catalog

Each app is one file in a git repository, written in DSC, Microsoft's open-source configuration format. furnish clones the repository on every computer and pulls changes every 30 minutes.

apps/gimp.dsc.yaml

metadata:
  furnish:
    description: Image editor for photo retouching, …
    categories: [Graphics, Photo]
    icon: icons/gimp.svg
    recommended: "[equals(parameters('role'), 'design')]"
resources:
  - name: gimp
    type: Furnish/Package
    condition: "[not(equals(context().os.family, 'Windows'))]"
    properties: { name: gimp }
  - name: gimp (winget)
    type: Furnish/Package
    condition: "[equals(context().os.family, 'Windows')]"
    properties: { name: GIMP.GIMP.3 }
  1. Describe the app: which package to install, with which package manager, on which systems.
  2. Push the file to the collection's repository.
  3. Everyone with the collection sees the app and can install it with their system's package manager.

A preview and live progress for each step

Before you install an app, furnish lists each step with the exact command and whether it needs an administrator password. During the install, the list shows which step runs and how long each took. You can stop after the current step or immediately.

Recommendations by role

A collection can ask what someone works on, for example software development or design, and recommend apps for the answer. Apps can also use the answer to decide how they install.

Kits

A kit installs several apps together, such as the apps a designer needs. Required apps are always included; people choose the optional ones.

Automatic updates

furnish installs updates by itself. While the computer is busy, by default over 50% CPU, 90% memory or 1000 KB/s network averaged over 5 minutes, it waits.

An install queue

When you start several installs, furnish runs them one after another. The Activity page lists what runs and what waits, and you can remove waiting installs.

For IT administrators

A policy decides which collections people get and what they may change. furnish reads it from each system's place for managed settings: a file on Linux, an MDM profile on macOS, Group Policy or Intune on Windows.

Installs without administrator rights

The furnish service installs the apps of your collections for people who aren't administrators. It accepts an app's name and option values, nothing else.

Sign-in without a VPN

Give furnish an address such as furnish.myorg.tld. People sign in with your organization's account, and furnish fetches your collections through a proxy that forwards only git's read requests. Your git server stays internal.

Signed collections

Preset collections can be limited to commits signed with your SSH keys. furnish's own Linux packages come from a signed APT and RPM repository.

Preset collections and locked settings

Add collections for everyone, answer their questions, install apps on first start, and lock any setting.

Your branding

furnish can show your organization's name, logo and color. It derives the other shades and keeps text readable in light and dark mode.

Install the alpha

Builds of the main branch, versioned 0.1.0+alpha.<build>. On Linux, updates arrive with your system's other updates.

sudo install -d /etc/apt/keyrings
sudo curl -fsSLo /etc/apt/keyrings/furnish.asc https://furnish-self-service.github.io/furnish/gpg-key.asc
sudo curl -fsSLo /etc/apt/sources.list.d/furnish.list https://furnish-self-service.github.io/furnish/alpha/furnish.list
sudo apt update && sudo apt install furnish
sudo curl -fsSLo /etc/yum.repos.d/furnish.repo https://furnish-self-service.github.io/furnish/alpha/furnish.repo
sudo dnf install furnish     # Enterprise Linux 10: enable EPEL and CRB first
sudo zypper addrepo https://furnish-self-service.github.io/furnish/alpha/furnish.repo
sudo zypper install furnish
# flake.nix
inputs.furnish.url = "github:furnish-self-service/furnish";

# configuration.nix, with furnish.nixosModules.default imported
services.furnish.enable = true;

Download for Mac with Apple silicon

The alpha isn't signed by Apple yet, so macOS blocks it at first: open furnish once, then allow it under System Settings → Privacy & Security → Open Anyway. A new alpha means a new download; furnish doesn't update itself on macOS yet. For Intel Macs, build it with Xcode's command line tools, Rust and Node.js:

git clone https://github.com/furnish-self-service/furnish.git
cd furnish/gui && npm ci && npm run bundle

Download for Windows (64-bit)

The alpha isn't code-signed yet, so Windows SmartScreen warns about it: choose More info → Run anyway. A new alpha means a new download; furnish doesn't update itself on Windows yet.

Then add your organization's furnish address or a collection's git URL on the Collections page. To try furnish, add the example collection: furnish collection add https://github.com/furnish-self-service/self-service-example.git.
