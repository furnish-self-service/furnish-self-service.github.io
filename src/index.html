People install the apps you approved with one click, and furnish keeps them updated with each system's own package manager. The catalog is a git repository on your git server. It runs on the systems you already have

furnish brings no server of its own. Each computer pulls the catalog from git and installs with the system's package manager. Choose your size to see which of your systems furnish uses.

furnish on every computer

a desktop app and a command, no central server

Your git server

GitHub, GitLab, Gitea, Forgejo or any server git reaches over HTTPS or SSH. One repository is the catalog; private ones work with a token or an SSH key.

The systems' package managers

apt, dnf, zypper, pacman, Nix, Homebrew and winget, and .deb, .rpm, .pkg, .dmg, .msi and .exe installers kept in the repository.

Device management

A policy from Intune, Group Policy, an MDM profile or a file in /etc decides which collections people get and locks settings.

Large organizations

Single sign-on

Your OpenID Connect provider, such as Entra ID, Keycloak or Authentik. People sign in once; furnish uses the sign-in for git and for reports.

Large organizations

Load balancer or reverse proxy

A furnish address behind Caddy, nginx, Traefik, Envoy or HAProxy, with tested configurations. It forwards git's read requests for the listed repositories only; the git server stays internal.

Large organizations

Log system

Vector passes furnish's reports to Loki, Elasticsearch, Splunk or a file. A Grafana dashboard comes with it.

Large organizations

A small team needs a git repository and furnish on each computer. People who are administrators of their computers install what they need; updates arrive by themselves.

A large organization adds what it already operates: rules from device management, sign-in from its identity provider, a proxy behind its load balancer and reports into its log system.

Small teams

Running in an afternoon

For a team whose people manage their own computers. There is nothing to host and no directory to connect.

  1. Put your apps in a git repository

    One short file per app says which package to install on which system. Start from the example collection with ten real apps.

  2. Install furnish on each computer

    From the signed package repository on Linux, or the download for macOS and Windows. Install instructions

  3. Add the repository

    Paste its URL on the Collections page, or run furnish collection add <url>. furnish pulls changes every 30 minutes and installs updates when the computer isn't busy.

  • furnish check in your repository's CI finds broken app files before anyone installs them.
  • When an install fails, furnish offers the version that last worked.
  • The app follows the system's language, English or German.

Large organizations

Rules your device management enforces, reports your log system keeps

furnish uses your device management, identity provider, load balancer and log system, so it fits the processes you already have for compliance and operations.

Enforce what people get

  • A policy from your device management presets collections people can't remove, answers their questions, locks settings and installs apps on first start.
  • People without administrator rights install through the furnish service, which accepts an app's name and the option values it declares, nothing else. You choose the group that may use it.
  • Preset collections only move to commits signed with your SSH keys, and never back to an older one.
  • Your organization's name, logo and color replace furnish's.

Keep an audit trail

  • furnish reports each install, update, uninstall and fallback with its outcome, the error, the device and the time. The proxy adds the user from the sign-in, so a computer can't report under someone else's name.
  • Reports go through Vector to your log system. The included Grafana dashboard shows failures per app, the furnish versions in use and devices that stopped reporting.
  • Reports are off until you turn them on, for failures only or for everything, and you can lock the choice. Works councils can review exactly which fields are sent.

Handle many computers

  • There is no catalog server to scale: every computer pulls from git, so your git server, or a mirror of it, carries the load.
  • Computers download only what they use: the history without old file contents, and installers only for the apps installed there.
  • A furnish address such as furnish.myorg.tld behind your load balancer replaces the VPN. People sign in with their organization account; the proxy forwards git's read requests for your listed repositories with a read-only deploy token.
  • An onboarding e-mail with a furnish:// link adds the address after one confirmation, and the address can install the VPN client or other first apps.

The admin guide covers the policy, the service and reports; the endpoint setup has the proxy configurations that CI tests.

For the people using it

People find the apps you approved, see what installing one will do, and get on with their work while furnish installs and updates in the background.

A preview and live progress for each step

Before you install an app, furnish lists each step with the exact command and whether it needs an administrator password. During the install, the list shows which step runs and how long each took. You can stop after the current step or immediately.

Recommendations by role

A collection can ask what someone works on, for example software development or design, and recommend apps for the answer. Apps can also use the answer to decide how they install.

Kits

A kit installs several apps together, such as the apps a designer needs. Required apps are always included; people choose the optional ones.

Automatic updates

furnish installs updates by itself. While the computer is busy, by default over 50% CPU, 90% memory or 1000 KB/s network averaged over 5 minutes, it waits.

An install queue

When you start several installs, furnish runs them one after another. The Activity page lists what runs and what waits, and you can remove waiting installs.

An earlier version when an install fails

If installing or updating an app fails, furnish offers the version that last worked and keeps it until the collection changes the app. Administrators decide whether furnish asks first, installs it right away or doesn't offer it.

In English and German

furnish follows the system's language, and people can switch it on the Collections page. Organizations can set it for everyone.

How an app gets into the catalog

Each app is one file in a git repository, written in DSC, Microsoft's open-source configuration format. furnish clones the repository on every computer and pulls changes every 30 minutes.

apps/gimp.dsc.yaml

metadata:
  furnish:
    description: Image editor for photo retouching, …
    categories: [Graphics, Photo]
    icon: icons/gimp.svg
    recommended: "[equals(parameters('role'), 'design')]"
resources:
  - name: gimp
    type: Furnish/Package
    condition: "[not(equals(context().os.family, 'Windows'))]"
    properties: { name: gimp }
  - name: gimp (winget)
    type: Furnish/Package
    condition: "[equals(context().os.family, 'Windows')]"
    properties: { name: GIMP.GIMP.3 }
  1. Describe the app: which package to install, with which package manager, on which systems.
  2. Push the file to the collection's repository.
  3. Everyone with the collection sees the app and can install it with their system's package manager.

Install the alpha

Builds of the main branch, versioned 0.1.0+alpha.<build>. On Linux, updates arrive with your system's other updates.

sudo install -d /etc/apt/keyrings
sudo curl -fsSLo /etc/apt/keyrings/furnish.asc https://furnish-self-service.github.io/furnish/gpg-key.asc
sudo curl -fsSLo /etc/apt/sources.list.d/furnish.list https://furnish-self-service.github.io/furnish/alpha/furnish.list
sudo apt update && sudo apt install furnish
sudo curl -fsSLo /etc/yum.repos.d/furnish.repo https://furnish-self-service.github.io/furnish/alpha/furnish.repo
sudo dnf install furnish     # Enterprise Linux 10: enable EPEL and CRB first
sudo zypper addrepo https://furnish-self-service.github.io/furnish/alpha/furnish.repo
sudo zypper install furnish
# flake.nix
inputs.furnish.url = "github:furnish-self-service/furnish";

# configuration.nix, with furnish.nixosModules.default imported
services.furnish.enable = true;

Download for Mac with Apple silicon

The alpha isn't signed by Apple yet, so macOS blocks it at first: open furnish once, then allow it under System Settings → Privacy & Security → Open Anyway. A new alpha means a new download; furnish doesn't update itself on macOS yet. For Intel Macs, build it with Xcode's command line tools, Rust and Node.js:

git clone https://github.com/furnish-self-service/furnish.git
cd furnish/gui && npm ci && npm run bundle

Download for Windows (64-bit)

The alpha isn't code-signed yet, so Windows SmartScreen warns about it: choose More info → Run anyway. A new alpha means a new download; furnish doesn't update itself on Windows yet.

Then add your organization's furnish address or a collection's git URL on the Collections page. To try furnish, add the example collection: furnish collection add https://github.com/furnish-self-service/self-service-example.git.
